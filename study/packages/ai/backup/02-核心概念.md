### 3.2 Simple 模式 (streamSimple/completeSimple)

**特点**:
- 统一的 `SimpleStreamOptions` 接口
- 自动处理 `reasoning` 参数映射到 Provider 特定选项
- 简化跨 Provider 切换

**定义**:
```typescript
export interface SimpleStreamOptions extends StreamOptions {
  reasoning?: ThinkingLevel;           // "minimal" | "low" | "medium" | "high" | "xhigh"
  thinkingBudgets?: ThinkingBudgets;   // 自定义 Token 预算
}
```

**使用**:
```typescript
import { streamSimple, completeSimple } from "@mariozechner/pi-ai";

// 统一的跨 Provider 接口
const stream = streamSimple(model, context, {
  reasoning: "medium",     // 自动映射到各 Provider 的推理参数
  temperature: 0.7,
});

// 支持 Provider 自动切换 (Handoff)
const message = await completeSimple(gpt4o, context, { reasoning: "high" });
const message2 = await completeSimple(claude, context, { reasoning: "high" });
// 相同的选项，自动适配不同 Provider
```

**reasoning 映射**:

| reasoning | OpenAI | Anthropic | Google |
|-----------|--------|-----------|--------|
| minimal | - | budget_tokens=1024 | - |
| low | effort="low" | budget_tokens=4000 | thinkingLevel=LOW |
| medium | effort="medium" | budget_tokens=16000 | thinkingLevel=MEDIUM |
| high | effort="high" | budget_tokens=32000 | thinkingLevel=HIGH |
| xhigh | - | budget_tokens=64000 | thinkingLevel=MAX |

## 4. 设计模式

### 4.1 策略模式 (Provider)

```
ApiProvider (接口)
    │
    ├── OpenAIResponsesProvider
    ├── AnthropicMessagesProvider
    ├── GoogleGenerativeAIProvider
    ├── MistralConversationsProvider
    └── ...
```

每个 Provider 实现相同的接口，但内部使用不同的 API 协议。

### 4.2 工厂模式 (Model)

```typescript
// 模型查找工厂
export function getModel(provider: Provider, id: string): Model {
  // 从 models.generated.ts 查找
  const models = getProviderModels(provider);
  return models.find(m => m.id === id);
}
```

### 4.3 观察者模式 (EventStream)

```typescript
// 事件流是观察者模式的实现
const stream = new AssistantMessageEventStream();

// Provider 推送事件
stream.push({ type: "text_delta", delta: "Hello" });
stream.push({ type: "text_delta", delta: " World" });
```

### 4.4 适配器模式 (Simple)

```typescript
// Simple 是适配器，将统一接口适配到各 Provider
function streamSimpleAnthropic(model, context, options) {
  // 将 SimpleStreamOptions 转换为 AnthropicOptions
```

### 4.5 代理模式 (Lazy Loading)

```typescript
// register-builtins.ts
export const streamAnthropic = createLazyStream(loadAnthropicProviderModule);

// 首次调用时才加载 Provider 实现
function createLazyStream(loadModule) {
  return (model, context, options) => {
    const outer = new AssistantMessageEventStream();
    loadModule().then(module => {
      const inner = module.stream(model, context, options);
      forwardStream(outer, inner);
    });
    return outer;
  };
}
```

## 5. 关键设计决策

### 5.1 为什么用 TypeBox 而不是 Zod？

```typescript
// TypeBox 优势：
// 1. 运行时类型 + 编译时类型一致性
const Schema = Type.Object({ name: Type.String() });
type T = Static<typeof Schema>;  // { name: string }

// 2. JSON Schema 标准兼容
const jsonSchema = JSON.stringify(Schema);  // 标准 JSON Schema

// 3. 更小的 bundle 体积
// 4. 更快的验证性能
```

### 5.2 为什么用 AsyncIterable 而不是 EventEmitter？

```typescript
// AsyncIterable 优势：
// 1. 符合语言标准
// 2. 支持 for await...of
// 3. 更好的类型安全
// 4. 更容易组合和转换

// EventEmitter 的问题：
// 1. 事件名是字符串，容易拼错
// 2. 类型安全差
// 3. 需要手动清理监听器
```

### 5.3 为什么区分 stream 和 streamSimple？

```typescript
// stream: 完全控制，Provider 特定选项
// 适合：需要精细控制、使用 Provider 特有功能

// streamSimple: 统一接口，跨 Provider 兼容
// 适合：需要跨 Provider 切换、不关心底层细节
```

### 5.4 懒加载 Provider 的好处

```typescript
// 1. 减少启动时间
// 2. 减少内存占用（只加载实际使用的 Provider）
// 3. 避免浏览器环境加载 Node-only 模块（如 Bedrock）
// 4. 支持代码分割
```

## 6. 与 pi-agent 的关系

```
┌─────────────────────────────────────────┐
│              pi-agent                   │
│  ┌─────────────────────────────────┐   │
│  │           Agent                 │   │
│  │  ┌─────────────────────────┐   │   │
│  │  │   agent-loop.ts         │   │   │
│  │  │  - 循环调用 LLM         │   │   │
│  │  │  - 处理 tool calls      │   │   │
│  │  └─────────────────────────┘   │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
                    │
                    ▼ 使用
┌─────────────────────────────────────────┐
│              pi-ai                      │
│  ┌─────────────────────────────────┐   │
│  │   stream(model, context)        │   │
│  │   complete(model, context)      │   │
│  │   ┌─────────────────────────┐   │   │
│  │   │  Provider 实现          │   │   │
│  │   │  - openai-responses     │   │   │
│  │   │  - anthropic-messages   │   │   │
│  │   └─────────────────────────┘   │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

**交互流程**:
1. `pi-agent` 的 `agent-loop` 调用 `pi-ai` 的 `stream()`
2. `pi-ai` 根据 `model.api` 路由到对应 Provider
3. Provider 发送 HTTP 请求到 LLM API
4. Provider 解析 SSE 流，转换为标准事件
5. `pi-ai` 返回 `AssistantMessageEventStream`
6. `pi-agent` 遍历流，处理文本增量和 tool calls
7. 如有 tool calls，`pi-agent` 执行工具并继续循环
