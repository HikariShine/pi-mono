# pi-ai 问题与坑

## 1. 高危坑点 🔴

### 1.1 Bedrock 只在 Node 环境可用

**问题**: Amazon Bedrock Provider 依赖 AWS SDK，只能在 Node.js 环境使用，浏览器环境会报错

**代码位置**: `providers/register-builtins.ts:180-200`

```typescript
// 特殊处理 Bedrock
function loadBedrockProviderModule() {
  if (bedrockProviderModuleOverride) {
    return Promise.resolve(bedrockProviderModuleOverride);
  }
  // 使用动态导入，避免浏览器打包
  bedrockProviderModulePromise ||= importNodeOnlyProvider("./amazon-bedrock.js")
    .then(...);
  return bedrockProviderModulePromise;
}
```

**解决方案**:
```typescript
// 检查环境
if (typeof window !== "undefined") {
  // 浏览器环境，不要使用 Bedrock
  const model = getModel("openai", "gpt-4o");
} else {
  // Node 环境，可以使用 Bedrock
  const model = getModel("amazon-bedrock", "claude-3-5-sonnet");
}
```

---

### 1.2 模型 ID 可能变化

**问题**: 提供商可能弃用或更改模型 ID，导致 `getModel` 找不到模型

**代码位置**: `models.generated.ts` (358KB 自动生成)

**问题场景**:
```typescript
// 模型 ID "gpt-4-turbo" 可能突然不可用
const model = getModel("openai", "gpt-4-turbo");  // 可能返回 undefined

// 没有检查直接使用
stream(model, context);  // 运行时错误！
```

**解决方案**:
```typescript
const model = getModel("openai", "gpt-4-turbo");
if (!model) {
  throw new Error("Model not found, please check model ID");
  // 或降级到默认模型
}
```

---

### 1.3 工具参数验证失败

**问题**: LLM 可能生成不符合 Schema 的参数，导致验证失败

**代码位置**: `utils/validation.ts`

```typescript
import { validateToolCall } from "@mariozechner/pi-ai";

try {
  const validatedArgs = validateToolCall(tools, toolCall);
} catch (error) {
  // 需要将错误返回给 LLM，让它重试修正
  context.messages.push({
    role: "toolResult",
    toolCallId: toolCall.id,
    toolName: toolCall.name,
    content: [{ type: "text", text: error.message }],
    isError: true,
    timestamp: Date.now(),
  });
}
```

**注意**: 如果不处理验证错误，整个流程会中断。

## 2. 中危坑点 🟡

### 2.1 ThinkingContent 可能被过滤

**问题**: 某些 Provider 可能出于安全原因过滤思考内容

**代码位置**: `types.ts:ThinkingContent`

```typescript
export interface ThinkingContent {
  type: "thinking";
  thinking: string;
  redacted?: boolean;  // 标记是否被过滤
}
```

**处理方案**:
```typescript
for (const content of message.content) {
  if (content.type === "thinking") {
    if (content.redacted) {
      console.log("Thinking content was redacted");
      // 使用 thinkingSignature 继续对话
    } else {
      console.log("Thinking:", content.thinking);
    }
  }
}
```

---

### 2.2 Image 输入支持不一致

**问题**: 不同 Provider 对图片输入的支持不同，可能报错

**代码位置**: `types.ts:Model.input`

```typescript
export interface Model {
  input: Array<"text" | "image">;  // 检查这个字段！
}
```

**使用检查**:
```typescript
if (!model.input.includes("image")) {
  // 不支持图片，需要过滤掉
  context.messages = context.messages.map(msg => ({
    ...msg,
    content: typeof msg.content === "string" 
      ? msg.content 
      : msg.content.filter(c => c.type !== "image")
  }));
}
```

**注意**: pi-ai 会自动过滤，但最好自己检查。

### 2.3 Reasoning 级别映射不一致

**问题**: 不同 Provider 对 reasoning 级别的支持不同

| reasoning | OpenAI | Anthropic | Google |
|-----------|--------|-----------|--------|
| minimal | ❌ | ✅ | ❌ |
| low | ✅ | ✅ | ✅ |
| medium | ✅ | ✅ | ✅ |
| high | ✅ | ✅ | ✅ |
| xhigh | ❌ | ✅ | ❌ |

**代码位置**: `providers/simple-options.ts`

**解决方案**:
```typescript
// 检查 Provider 支持
try {
  const stream = streamSimple(model, context, { reasoning: "xhigh" });
} catch (error) {
  // 降级到支持的级别
  const stream = streamSimple(model, context, { reasoning: "high" });
}
```

## 3. 低危坑点 🟢

### 3.1 模型成本计算可能不准确

**问题**: `Usage.cost` 是估算值，可能与实际账单有差异

**代码位置**: `types.ts:Usage`

```typescript
export interface Usage {
  cost: {
    input: number;   // 估算值
    output: number;  // 估算值
    total: number;   // 估算值
  };
}
```

**注意**: 用于粗略估算，不要用于计费。

---

### 3.2 消息时间戳精度

**问题**: `timestamp` 是毫秒级 Unix 时间戳，但要注意时区

**代码位置**: `types.ts:UserMessage.timestamp`

```typescript
interface UserMessage {
  timestamp: number;  // Date.now()，毫秒
}
```

**使用**:
```typescript
const msg: UserMessage = {
  role: "user",
  content: "Hello",
  timestamp: Date.now(),  // 当前时间
};
```

---

### 3.3 流式事件顺序

**问题**: Provider 的事件顺序可能不同，不要假设固定顺序

**OpenAI**:
```
start → text_delta → text_delta → ... → done
```

**Anthropic** (带 thinking):
```
start → thinking_delta → ... → text_delta → ... → done
```

**注意**: 始终使用 `event.type` 判断。

---

### 3.4 工具调用 ID 格式

**问题**: 不同 Provider 的工具调用 ID 格式不同

- OpenAI: `call_xxx`
- Anthropic: `toolu_xxx`
- Google: 数字 ID

**注意**: 只用于关联 toolResult，不要依赖格式。

## 5. 最佳实践

### 5.1 始终处理错误

```typescript
try {
  const stream = stream(model, context);
  for await (const event of stream) {
    if (event.type === "error") {
      console.error("Stream error:", event.error);
      return;
    }
    // ...
  }
} catch (error) {
  console.error("Unexpected error:", error);
}
```

### 5.2 验证工具调用

```typescript
import { validateToolCall } from "@mariozechner/pi-ai";

if (event.type === "toolcall_end") {
  try {
    const args = validateToolCall(tools, event.toolCall);
    // 执行工具
    const result = await executeTool(event.toolCall.name, args);
  } catch (error) {
    // 返回错误给 LLM
    context.messages.push({
      role: "toolResult",
      toolCallId: event.toolCall.id,
      toolName: event.toolCall.name,
      content: [{ type: "text", text: error.message }],
      isError: true,
      timestamp: Date.now(),
    });
  }
}
```

### 5.3 使用 Simple 模式简化跨 Provider

```typescript
// 如果不需要 Provider 特定功能，使用 Simple
const stream = streamSimple(model, context, {
  reasoning: "medium",  // 自动映射到各 Provider
});
```

### 5.4 缓存模型列表

```typescript
import { getProviderModels } from "@mariozechner/pi-ai";

// 缓存模型列表，避免重复查找
const modelCache = new Map<string, Model>();

function getCachedModel(provider: string, id: string): Model | undefined {
  const key = `${provider}:${id}`;
  if (!modelCache.has(key)) {
    const model = getModel(provider, id);
    if (model) modelCache.set(key, model);
  }
  return modelCache.get(key);
}
```
