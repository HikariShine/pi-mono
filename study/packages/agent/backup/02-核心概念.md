# pi-agent-core 核心概念

## 1. AgentMessage vs Message

### AgentMessage (Agent 层)

灵活的内部消息格式，支持扩展：

```typescript
interface AgentMessage {
  role: "user" | "assistant" | "toolResult" | "custom" | "notification";
  content: (TextContent | ImageContent | ToolCall | ToolResult)[];
  timestamp: number;
  // ... 其他字段
}
```

**特点**：
- 支持自定义消息类型（通过 TypeScript declaration merging）
- 包含 UI 专用的消息（如 notification）
- 携带元数据（timestamp、usage、stopReason 等）

### Message (LLM 层)

来自 `@mariozechner/pi-ai`，LLM 能理解的格式：

```typescript
type Message = UserMessage | AssistantMessage | ToolResultMessage;
```

**特点**：
- 只包含 LLM 能处理的角色（user/assistant/toolResult）
- 标准 OpenAI 兼容格式

### 转换流程

```
AgentMessage[] 
  → transformContext() [可选]  →  AgentMessage[] 
  → convertToLlm() [必需]     →  Message[] 
  → LLM 调用
```

**关键**：`convertToLlm` 必须过滤掉非 LLM 兼容的消息类型。

## 2. AgentState (状态)

Agent 运行时的完整状态快照：

| 字段 | 类型 | 含义 |
|------|------|------|
| `systemPrompt` | `string` | 系统提示词 |
| `model` | `Model<any>` | 当前使用的模型 |
| `thinkingLevel` | `ThinkingLevel` | 推理级别（off/minimal/low/medium/high/xhigh）|
| `tools` | `AgentTool[]` | 注册的工具列表 |
| `messages` | `AgentMessage[]` | 完整对话历史 |
| `isStreaming` | `boolean` | 是否正在流式响应 |
| `streamMessage` | `AssistantMessage \| null` | 当前流式消息（partial）|
| `pendingToolCalls` | `Set<string>` | 正在执行的 tool call IDs |
| `error` | `string \| undefined` | 最后错误信息 |

**访问方式**：`agent.state`（只读）

---

## 3. AgentContext (上下文)

单次 LLM 调用所需的上下文：

```typescript
interface AgentContext {
  systemPrompt: string;      // 系统提示词
  messages: AgentMessage[];  // 当前消息列表（引用！）
  tools: AgentTool[];        // 可用工具
}
```

**注意**：`messages` 是**引用**，`push()` 会修改原数组。

---

## 4. AgentLoopConfig (循环配置)

控制 Agent 循环行为的配置：

| 配置项 | 类型 | 说明 |
|--------|------|------|
| `model` | `Model<any>` | 使用的 LLM 模型 |
| `convertToLlm` | `(msgs) => Message[]` | **必需** 消息转换函数 |
| `transformContext` | `(msgs) => Promise<AgentMessage[]>` | 可选 上下文转换 |
| `toolExecution` | `"parallel" \| "sequential"` | 工具执行模式 |
| `beforeToolCall` | `(ctx) => Promise<BeforeToolCallResult>` | 工具调用前钩子 |
| `afterToolCall` | `(ctx) => Promise<AfterToolCallResult>` | 工具调用后钩子 |
| `steeringMode` | `"all" \| "one-at-a-time"` | 转向消息处理模式 |
| `followUpMode` | `"all" \| "one-at-a-time"` | 跟进消息处理模式 |

## 5. 工具定义 AgentTool

```typescript
interface AgentTool<T> {
  name: string;                    // 工具名（唯一标识）
  label: string;                   // 显示名称（UI用）
  description: string;             // 功能描述（给LLM看）
  parameters: TSchema;             // JSON Schema 参数定义
  execute: (
    toolCallId: string,           // 调用ID
    params: Static<T>,            // 验证后的参数
    signal?: AbortSignal,         // 取消信号
    onUpdate?: (update) => void   // 流式更新回调
  ) => Promise<AgentToolResult<any>>;
}
```

### AgentToolResult

```typescript
interface AgentToolResult<T> {
  content: (TextContent | ImageContent)[];  // 返回内容
  details?: T;                              // 结构化详情
}
```

**错误处理**：`execute` 中 throw error，Agent 会自动包装为 `isError: true` 的结果。

## 6. 事件系统 AgentEvent

Agent 通过事件通知状态变化：

### 事件类型

| 事件 | 触发时机 | 携带数据 |
|------|----------|----------|
| `agent_start` | Agent 开始处理 | - |
| `agent_end` | Agent 完成 | `messages: AgentMessage[]` |
| `turn_start` | 新回合开始（一次 LLM 调用）| - |
| `turn_end` | 回合结束 | `message, toolResults` |
| `message_start` | 消息开始 | `message: AgentMessage` |
| `message_update` | 消息更新（流式）| `message, assistantMessageEvent` |
| `message_end` | 消息完成 | `message: AgentMessage` |
| `tool_execution_start` | 工具开始执行 | `toolCallId, toolName, args` |
| `tool_execution_update` | 工具进度更新 | `toolCallId, partialResult` |
| `tool_execution_end` | 工具执行完成 | `toolCallId, result` |

### 订阅方式

```typescript
const unsubscribe = agent.subscribe((event) => {
  console.log(event.type);
});

// 取消订阅
unsubscribe();
```

## 7. 消息队列

### Steering Queue（转向队列）

在 Agent 运行时插入消息，中断当前流程：

```typescript
agent.setSteeringMode("one-at-a-time"); // 或 "all"
agent.steer({ role: "user", content: "Stop!", timestamp: Date.now() });
```

**执行时机**：当前回合的所有 tool calls 完成后，下回合开始前。

### Follow-up Queue（跟进队列）

在 Agent 即将停止时追加消息，继续对话：

```typescript
agent.setFollowUpMode("one-at-a-time"); // 或 "all"
agent.followUp({ role: "user", content: "Also...", timestamp: Date.now() });
```

**执行时机**：没有更多 tool calls 和 steering messages 时。

### 模式对比

| 模式 | 行为 |
|------|------|
| `"one-at-a-time"` | 每次只取一条消息处理 |
| `"all"` | 一次性取全部消息处理 |

## 8. prompt() vs continue()

### prompt(message)

- **用途**：发送新消息，启动对话
- **前置条件**：`isStreaming === false`（不在处理中）
- **行为**：添加消息到队列，启动 Agent 循环

### continue()

- **用途**：从当前上下文继续，不重发消息
- **前置条件**：最后一条消息不是 `assistant`（需要 `user` 或 `toolResult`）
- **场景**：工具执行失败后重试、恢复中断的对话

## 9. 工具执行模式

### parallel（默认）

```
准备 A → 准备 B → 准备 C
                ↓
         [并行执行 A、B、C]
                ↓
按顺序返回结果（A → B → C）
```

**适用**：独立工具（如查天气+查股票）

### sequential

```
准备 A → 执行 A → 完成 A → 
准备 B → 执行 B → 完成 B → 
准备 C → 执行 C → 完成 C
```

**适用**：有依赖的工具（如先读文件再修改）

## 10. 流式响应机制

```
User: "Hello"
  ↓
LLM 开始生成 → emit "message_start"
  ↓
逐字符/逐 token → emit "message_update" (多次)
  ↓
生成完成 → emit "message_end"
  ↓
检查 toolCalls → 如果有 → 执行工具 → emit tool events
  ↓
emit "turn_end"
```

**关键**：`streamMessage` 字段在流式期间持有 partial 消息，流式结束后置为 `null`。

## 11. 工具钩子

### beforeToolCall

在工具执行前调用，可以拦截：

```typescript
beforeToolCall: async ({ toolCall, args, context }) => {
  if (toolCall.name === "bash") {
    return { block: true, reason: "Security: bash disabled" };
  }
  // 返回 undefined 表示允许执行
}
```

### afterToolCall

在工具执行后调用，可以修改结果：

```typescript
afterToolCall: async ({ toolCall, result, isError, context }) => {
  if (!isError) {
    return { details: { ...result.details, audited: true } };
  }
  // 返回 undefined 表示不做修改
}
```

**执行顺序**：
```
tool_execution_start → beforeToolCall → execute() → afterToolCall → tool_execution_end
```
