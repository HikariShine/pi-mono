# agent 问题与坑

## 1. Agent Loop 陷阱

### 1.1 Loop 竞争条件

**问题**：`agent.prompt()` 可能在前一个 loop 未完成时被调用。

**坑点**：
```typescript
// 错误：直接启动新 loop
agent.prompt("message 1");
agent.prompt("message 2");  // 可能冲突！
```

**解决**：
```typescript
// pi-agent-core 的实现
private runningPrompt?: Promise<void>;

async prompt(message: AgentMessage) {
  this.enqueueSteeringMessage(message);
  
  // 如果 loop 未运行，启动新 loop
  if (!this.runningPrompt) {
    this.runningPrompt = this.startAgentLoop();
    await this.runningPrompt;
    this.runningPrompt = undefined;
  }
  // 否则消息已进入 steeringQueue，loop 会自动处理
}
```

---

### 1.2 continue 的约束

**问题**：`agentLoopContinue()` 有前置条件。

**坑点**：
```typescript
// 错误：没有消息时 continue
agentLoopContinue({ messages: [], tools: [] }, config);
// 抛出: "Cannot continue: no messages in context"

// 错误：最后一条是 assistant 消息时 continue
agentLoopContinue({ 
  messages: [{ role: "assistant", ... }] 
}, config);
// 抛出: "Cannot continue from message role: assistant"
```

**解决**：
- 确保最后一条消息是 `user` 或 `toolResult`
- 使用场景：重试、继续处理 tool results

## 2. 消息转换陷阱

### 2.1 convertToLlm 遗漏

**问题**：自定义消息类型未在 `convertToLlm` 中处理。

**坑点**：
```typescript
// 发送自定义消息
agent.prompt({ role: "custom", content: "..." });

// 默认 convertToLlm 过滤掉非标准消息
// 结果：LLM 看不到这条消息！
```

**解决**：
```typescript
const agent = new Agent({
  convertToLlm: (messages) => messages.flatMap(m => {
    if (m.role === "custom") {
      // 转换为 user 消息
      return [{ 
        role: "user", 
        content: m.content,
        timestamp: m.timestamp 
      }];
    }
    // 标准消息直接通过
    if (m.role === "user" || m.role === "assistant" || m.role === "toolResult") {
      return [m];
    }
    // 过滤其他
    return [];
  })
});
```

---

### 2.2 transformContext 时机

**问题**：`transformContext` 在 `convertToLlm` 之前调用。

**坑点**：
```typescript
// 错误理解：以为 transformContext 看到的是 Message[]
transformContext: (messages) => {
  // messages 是 AgentMessage[]，不是 Message[]！
  messages.forEach(m => {
    // m 可能有 role === "custom"，不是标准 Message
  });
}
```

**正确流程**：
1. `transformContext(AgentMessage[])` → `AgentMessage[]`
2. `convertToLlm(AgentMessage[])` → `Message[]`

## 3. 工具执行陷阱

### 3.1 并发执行限制

**问题**：并行模式 (`"parallel"`) 下，工具之间可能冲突。

**坑点**：
```typescript
// 两个工具同时修改同一文件
// Tool A: read file X
// Tool B: write file X
// 结果：竞争条件！
```

**解决**：
- 使用 `"sequential"` 模式（默认是 `"parallel"`）
- 在工具实现中加锁

```typescript
const agent = new Agent({
  toolExecution: "sequential"  // 顺序执行
});
```

---

### 3.2 beforeToolCall 返回值

**问题**：`beforeToolCall` 返回 `undefined` 与返回 `{}` 的区别。

**坑点**：
```typescript
// 返回 undefined：继续执行
beforeToolCall: async () => undefined

// 返回 {}：继续执行 (空对象也是 truthy)
beforeToolCall: async () => ({})

// 返回 { block: true }：阻止执行
beforeToolCall: async () => ({ block: true })
```

**注意**：返回 `undefined` 和 `{}` 都是"继续执行"。

---

### 3.3 afterToolCall 字段覆盖

**问题**：`afterToolCall` 返回的对象会**完全覆盖**原字段。

**坑点**：
```typescript
afterToolCall: (context) => {
  // 只修改 isError，content 和 details 会丢失！
  return { isError: false };
}

// 正确：保留原字段
afterToolCall: (context) => {
  return {
    content: context.result.content,  // 保留
    details: context.result.details,  // 保留
    isError: false  // 修改
  };
}
```

## 4. 事件系统陷阱

### 4.1 事件同步发射

**问题**：事件是**同步**发射的。

**坑点**：
```typescript
agent.addListener(async (event) => {
  // 异步处理
  await saveToDatabase(event);
});

// 注意：listener 中的 await 不会阻塞 loop
// loop 会继续执行，可能事件还没保存就完成了
```

**解决**：
- 如果需要等待，使用 `await emit()`（内部实现是 await 所有 listeners）
- pi-agent-core 的 `emit` 确实会 `await` 每个 listener

---

### 4.2 streamMessage 更新

**问题**：`streamMessage` 只在 `message_update` 时更新。

**坑点**：
```typescript
// 检查 streamMessage
console.log(agent.state.streamMessage);  // 可能不是最新的

// 正确：监听事件
agent.addListener((event) => {
  if (event.type === "message_update") {
    console.log(event.message);  // 最新的
  }
});
```

## 5. Proxy 陷阱

### 5.1 Proxy 流重建

**问题**：Proxy 服务器发送的是 delta 事件，需要客户端重建 partial message。

**坑点**：
```typescript
// Proxy 事件没有 partial 字段 (节省带宽)
// 客户端需要自己维护 partial 状态

const partial: AssistantMessage = { ... };

for await (const event of proxyStream) {
  if (event.type === "text_delta") {
    partial.content[event.contentIndex].text += event.delta;
  }
  // ...
}
```

---

### 5.2 Proxy 认证

**问题**：`authToken` 可能在长时间运行中过期。

**解决**：
```typescript
const agent = new Agent({
  streamFn: async (model, context, options) => {
    // 每次调用获取新的 token
    const token = await getFreshAuthToken();
    return streamProxy(model, context, {
      ...options,
      authToken: token,
      proxyUrl: "https://..."
    });
  }
});
```

## 6. 状态管理陷阱

### 6.1 状态修改不触发事件

**问题**：直接修改 `agent.state` 不会触发事件。

**坑点**：
```typescript
// 错误：直接修改
agent.state.messages.push(newMessage);  // 不会触发事件！

// 正确：通过 prompt
await agent.prompt(newMessage);  // 会触发完整流程
```

**注意**：`agent.state` 是只读的，应该使用 `agent.setXxx()` 方法。

---

### 6.2 pendingToolCalls 管理

**问题**：`pendingToolCalls` 自动管理，不要手动修改。

**坑点**：
```typescript
// 不要手动操作
agent.state.pendingToolCalls.add("id");  // 错误！

// 由 loop 自动管理
// - tool_execution_start 时添加
// - tool_execution_end 时移除
```

---

## 7. AbortSignal 陷阱

### 7.1 Signal 传递

**问题**：`AbortSignal` 需要正确传递到所有异步操作。

**坑点**：
```typescript
beforeToolCall: async (context, signal) => {
  // 错误：没传递 signal
  await fetch("/api/check");  // 无法取消！
  
  // 正确：传递 signal
  await fetch("/api/check", { signal });
}
```

---

## 8. 内存陷阱

### 8.1 消息累积

**问题**：`messages` 数组会无限增长。

**坑点**：
```typescript
// 长时间运行，messages 可能非常大
// 导致内存溢出

// 解决：使用 transformContext 裁剪
transformContext: async (messages) => {
  if (estimateTokens(messages) > MAX_TOKENS) {
    return pruneOldMessages(messages);
  }
  return messages;
}
```

## 10. 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `Cannot continue: no messages` | `agentLoopContinue` 没有消息 | 先添加消息 |
| `Cannot continue from assistant` | 最后消息是 assistant | 确保最后是 user/toolResult |
| `Tool not found` | 工具未注册 | `agent.addTool(tool)` |
| `Tool validation failed` | 参数不符合 schema | 检查参数类型 |
| `Stream error` | LLM 调用失败 | 检查 API key、网络 |
| `Tool blocked` | `beforeToolCall` 返回 block | 检查 hook 逻辑 |
| `Max tokens exceeded` | 上下文超限 | 使用 `transformContext` 裁剪 |
| `Proxy error` | 代理服务器错误 | 检查 proxyUrl、authToken |

## 11. 最佳实践

### 11.1 错误处理

```typescript
agent.addListener(async (event) => {
  if (event.type === "agent_end") {
    const lastMessage = event.messages[event.messages.length - 1];
    if (lastMessage?.stopReason === "error") {
      console.error("Agent error:", lastMessage.errorMessage);
    }
  }
});
```
