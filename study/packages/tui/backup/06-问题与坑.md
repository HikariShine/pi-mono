# pi-tui 问题与坑

## 1. 高危坑点 🔴

### 1.1 行宽度溢出崩溃

**问题**: 如果组件渲染的行超过终端宽度，TUI 会崩溃

**代码位置**: `tui.ts:1060-1100`

```typescript
if (!isImage && visibleWidth(line) > width) {
  // 记录崩溃日志到 ~/.pi/agent/pi-crash.log
  fs.writeFileSync(crashLogPath, crashData);
  
  // 清理终端状态
  this.stop();
  
  // 抛出错误
  throw new Error(`Rendered line ${i} exceeds terminal width...`);
}
```

**原因**:
- 终端行为不可预测
- 可能导致显示错乱或终端损坏

**解决方案**:
```typescript
// 组件必须确保行宽度不超过 width
render(width: number): string[] {
  let lines = ...;
  // 使用工具函数截断
  return lines.map(line => truncateToWidth(line, width));
}
```

**预防措施**:
- 使用 `visibleWidth()` 测量
- 使用 `truncateToWidth()` 截断
- 使用 `sliceByColumn()` 精确切片

### 1.2 CSI 2026 同步输出不支持

**问题**: 部分终端不支持 CSI 2026，可能导致闪烁

**影响**:
- Windows CMD
- 部分旧版终端
- 某些 SSH 客户端

**代码位置**: `tui.ts:855-862`

```typescript
let buffer = "\x1b[?2026h";  // 开始同步
// ... 渲染内容 ...
buffer += "\x1b[?2026l";     // 结束同步
```

**解决方案**:
- 终端会忽略不认识的序列，不会崩溃
- 但失去原子化更新，可能闪烁
- 建议用户使用支持 CSI 2026 的终端（iTerm2、Windows Terminal、Kitty 等）

---

### 1.3 Kitty 协议兼容性问题

**问题**: 不同终端对 Kitty 键盘协议的支持程度不同

**已知问题**:
- Windows Terminal：部分支持，可能丢失释放事件
- VS Code 终端：不支持
- 某些 SSH 客户端：可能过滤序列

**代码位置**: `terminal.ts:110-130`

```typescript
// 检测响应
const match = sequence.match(/^\x1b\[(\d+)u$/);
if (match) {
  this._kittyProtocolActive = true;
  // 启用所有标志
  process.stdout.write("\x1b[>7u");
}
```

**应对策略**:
- 优雅降级到传统模式
- 不依赖 release 事件做关键功能
- 使用 `isKittyProtocolActive()` 检查状态

### 2.2 弹层焦点管理复杂

**问题**: 多层弹层 + 响应式 `visible` 回调，焦点管理容易出错

**代码位置**: `tui.ts:515-530`

```typescript
// 输入处理时检查聚焦弹层是否还可见
const focusedOverlay = this.overlayStack.find(o => o.component === this.focusedComponent);
if (focusedOverlay && !this.isOverlayVisible(focusedOverlay)) {
  // 聚焦的弹层不再可见，重定向焦点
  const topVisible = this.getTopmostVisibleOverlay();
  this.setFocus(topVisible?.component ?? focusedOverlay.preFocus);
}
```

**潜在问题**:
- `visible` 回调在每次渲染时调用
- 可能导致焦点意外跳转
- 多层弹层关闭时焦点恢复顺序

**建议**:
- 谨慎使用 `visible` 回调
- 测试多层弹层的焦点恢复
- 使用 `nonCapturing` 避免自动聚焦问题

### 2.3 图片渲染的行高度计算

**问题**: 终端图片可能占用多行，但 `render()` 返回的是字符串数组

**代码位置**: `terminal-image.ts`

```typescript
export function calculateImageRows(
  widthPx: number, 
  heightPx: number, 
  cellHeight: number

  return Math.ceil(heightPx / cellHeight);
}
```

**问题场景**:
- 单元格尺寸查询可能失败
- 图片行在差异化渲染中被跳过

**代码位置**: `tui.ts:780`

```typescript
// 差异化渲染跳过图片行
if (isImageLine(line)) {
  // 图片行总是全量更新

}
```

### 3.1 Termux 高度变化特殊处理

**问题**: Android Termux 键盘弹出/隐藏会改变终端高度

**代码位置**: `tui.ts:900-910`

```typescript
// 高度变化通常需要全量重绘，但 Termux 例外
if (heightChanged && !isTermuxSession()) {
  fullRender(true);
  return;
}
```

**原因**: Termux 键盘切换频繁，全量重绘会导致历史内容反复重播

**检测**:
```typescript
function isTermuxSession(): boolean {
  return Boolean(process.env.TERMUX_VERSION);
}
```

### 3.4 clearOnShrink 配置

**问题**: 内容缩小时是否清除空行是可配置的，但默认行为可能不符合预期

**代码位置**: `tui.ts:915-920`

```typescript
if (this.clearOnShrink && newLines.length < this.maxLinesRendered && this.overlayStack.length === 0) {
  fullRender(true);
  return;
}
```

**默认**: `clearOnShrink = false`（环境变量 `PI_CLEAR_ON_SHRINK`）

**影响**:
- true: 内容缩小时清除空行，保持整洁
- false: 空行保留，减少慢终端的重绘

## 5. 最佳实践

### 5.1 组件开发

```typescript
class MyComponent implements Component {
  render(width: number): string[] {
    // 1. 生成内容
    let lines = this.generateContent();
    
    // 2. 确保每行不超过 width
    lines = lines.map(line => {
      if (visibleWidth(line) > width) {
        return truncateToWidth(line, width);
      }
      return line;
    });
    
    // 3. 返回
    return lines;
  }
  
  invalidate(): void {
    // 清除缓存
    this.cache = null;
  }
}
```

## 6. 常见问题 FAQ

**Q: 为什么有闪烁？**
A: 终端不支持 CSI 2026，或 SSH 连接延迟高。尝试使用 iTerm2、Kitty 或 Windows Terminal。

**Q: 中文显示错位？**
A: 确保使用 `visibleWidth()` 和 `truncateToWidth()` 处理东亚字符。

**Q: 图片不显示？**
A: 检查终端是否支持 Kitty 或 iTerm2 图片协议。运行 `detectCapabilities()` 查看支持情况。

**Q: 键盘快捷键不工作？**
A: 检查终端是否支持 Kitty 键盘协议。使用 `isKittyProtocolActive()` 检查状态。

**Q: 如何测试组件？**
A: 使用 `VirtualTerminal`（测试专用实现），避免依赖真实终端。
