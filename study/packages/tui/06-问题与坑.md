# pi-tui 问题与坑

## 1. 差异化渲染陷阱

### 1.1 行尾空格丢失

**问题**：终端通常会自动截断行尾空格。

**坑点**：
```typescript
// 错误：依赖行尾空格定位
render(width) {
  return ["Hello    "];  // 空格可能被截断
}

// 正确：使用光标定位
render(width) {
  return ["Hello\x1b[4C"];  // 光标右移 4 列
}
```

### 1.2 ANSI 序列在 diff 中的处理

**问题**：ANSI 转义序列参与 diff 比较可能导致问题。

**坑点**：
```typescript
// 如果两个行视觉上相同但 ANSI 不同
const line1 = "\x1b[31mred\x1b[0m";      // 红色
const line2 = "\x1b[38;5;196mred\x1b[0m"; // 也是红色

// diff 会认为它们不同，触发不必要的重绘
```

**解决**：
- 规范化 ANSI 序列（如果性能允许）
- 接受偶尔的多余重绘（通常无害）

### 1.3 宽字符宽度计算

**问题**：CJK 字符和中文字符宽度 = 2。

**坑点**：
```typescript
// 错误：假设所有字符宽度为 1
const width = text.length;  // 错误！

// 正确：使用 visibleWidth
import { visibleWidth } from "@mariozechner/pi-tui";
const width = visibleWidth("hello 世界");  // 10 (不是 8)
```

## 2. 键盘输入陷阱

### 2.1 Kitty 协议兼容性

**问题**：不是所有终端都支持 Kitty 协议。

**坑点**：
```typescript
// 错误：假设 Kitty 协议总是启用
if (isKeyRelease(data)) {  // 传统终端不支持！
  // 不会触发
}
```

**解决**：
```typescript
// 检查协议状态
if (isKittyProtocolActive() && isKeyRelease(data)) {
  // 处理释放事件
}
```

### 2.2 组合键冲突

**问题**：某些组合键与终端快捷键冲突。

| 按键 | 冲突 |
|------|------|
| Ctrl+c | SIGINT (中断信号) |
| Ctrl+z | SIGTSTP (挂起) |
| Ctrl+d | EOF |
| Ctrl+s | XOFF (暂停输出) |
| Ctrl+q | XON (恢复输出) |

**解决**：
- 使用 raw mode 避免大多数冲突
- 对于 Ctrl+c，需要自己处理复制而不是终止

### 2.3 批量输入分割

**问题**：用户快速输入时，多个按键可能在一个 data 事件中到达。

**坑点**：
```typescript
// 错误：假设每个 data 是一个按键
stdin.on("data", (data) => {
  if (matchesKey(data, Key.Enter)) {
    // data 可能是 "abc" 而不仅是 Enter
  }
});
```

**解决**：
```typescript
// 正确：使用 StdinBuffer
const buffer = new StdinBuffer({ timeout: 10 });
buffer.on("data", (sequence) => {
  // 每个 sequence 是一个独立按键
});
```

## 3. 焦点管理陷阱

### 3.1 焦点丢失

**问题**：显示覆盖层后，原焦点组件失去焦点。

**坑点**：
```typescript
const overlay = tui.showOverlay(dialog);  // 焦点自动转移到 overlay
dialog.close();
// 焦点不会自动回到之前的位置！
```

**解决**：
```typescript
const prevFocus = tui.getFocusedComponent();
const overlay = tui.showOverlay(dialog, { nonCapturing: true });  // 不抢焦点
// 或者手动恢复
dialog.onClose = () => {
  if (prevFocus) tui.focus(prevFocus);
};
```

### 3.2 CURSOR_MARKER 遗漏

**问题**：自定义 Focusable 组件忘记插入 CURSOR_MARKER。

**坑点**：
```typescript
class MyEditor implements Focusable {
  focused = false;

  render(width) {
    return ["Hello"];  // 错误：没有 CURSOR_MARKER！
  }
}

// 结果：硬件光标位置错误，IME 窗口位置错误
```

**解决**：
```typescript
render(width) {
  if (this.focused) {
    return ["Hel" + CURSOR_MARKER + "lo"];
  }
  return ["Hello"];
}
```

## 4. 覆盖层陷阱

### 4.1 覆盖层堆叠顺序

**问题**：多个覆盖层的 z-index 管理。

**坑点**：
```typescript
const overlay1 = tui.showOverlay(comp1);
const overlay2 = tui.showOverlay(comp2);

// overlay2 在 overlay1 上面
// 但无法直接控制顺序
```

**解决**：
- 后创建的覆盖层在上面
- 使用 `overlay.focus()` 将覆盖层移到最前

### 4.2 覆盖层尺寸计算

**问题**：百分比尺寸在终端大小变化时需要重新计算。

**坑点**：
```typescript
const overlay = tui.showOverlay(comp, {
  width: "50%",
  anchor: "center"
});

// 终端大小变化后，覆盖层不会自动调整
```

**解决**：
```typescript
// 监听 resize
terminal.start(onInput, () => {
  // 终端大小变化，重新渲染
  tui.render();
  // overlay 会在下次 render 时重新计算位置
});
```

## 5. 终端图像陷阱

### 5.1 图像 ID 冲突

**问题**：Kitty 图像协议使用 ID 管理图像。

**坑点**：
```typescript
// 错误：重复使用相同 ID
renderImage(data1, { imageId: 1 });
renderImage(data2, { imageId: 1 });  // 覆盖第一张图
```

**解决**：
```typescript
import { allocateImageId } from "@mariozechner/pi-tui";

const id1 = allocateImageId();  // 自动分配唯一 ID
const id2 = allocateImageId();
```

### 5.2 图像清理

**问题**：图像显示后占用终端内存，不会自动清理。

**坑点**：
```typescript
// 显示图像
renderImage(data, { imageId: 1 });

// 图像会一直保留，即使不可见
```

**解决**：
```typescript
import { deleteKittyImage, deleteAllKittyImages } from "@mariozechner/pi-tui";

// 删除单个
deleteKittyImage(1);

// 删除所有
deleteAllKittyImages();
```

### 5.3 终端兼容性

**问题**：不是所有终端都支持图像协议。

| 终端 | Kitty | iTerm2 |
|------|-------|--------|
| iTerm2 | ❌ | ✅ |
| kitty | ✅ | ❌ |
| WezTerm | ✅ | ✅ |
| GNOME Terminal | ❌ | ❌ |

**解决**：
```typescript
const caps = detectCapabilities();

if (caps.kitty) {
  renderImage(data, { protocol: "kitty" });
} else if (caps.iterm2) {
  renderImage(data, { protocol: "iterm2" });
} else {
  // 回退：显示占位符
  console.log("[Image not supported]");
}
```

## 6. 自动补全陷阱

### 6.1 异步建议竞争

**问题**：用户快速输入时，旧建议可能晚于新建议到达。

**坑点**：
```typescript
// 错误：不检查顺序
async getSuggestions(input) {
  const results = await fetch(`/api/suggest?q=${input}`);
  return results;  // 可能过时！
}
```

**解决**：
```typescript
let requestId = 0;

async getSuggestions(input) {
  const id = ++requestId;
  const results = await fetch(`/api/suggest?q=${input}`);
  
  if (id !== requestId) {
    return { items: [] };  // 丢弃过时结果
  }
  
  return results;
}
```

### 6.2 模糊匹配性能

**问题**：大量候选项时，模糊匹配可能很慢。

**坑点**：
```typescript
// 错误：对所有候选项匹配
const results = fuzzyFilter(10000_items, query);  // 卡顿！
```

**解决**：
- 限制候选项数量（如前 100 个）
- 使用 debounce 延迟搜索
- 考虑使用 worker 线程

## 7. 编辑器陷阱

### 7.1 粘贴处理

**问题**：大段粘贴可能导致性能问题。

**坑点**：
```typescript
// 用户粘贴 1000 行代码
// 如果不优化，会触发 1000 次 render
```

**解决**：
```typescript
// Editor 使用 bracketed paste 检测
// 完整粘贴内容一次性处理
handleInput(data) {
  if (isBracketedPaste(data)) {
    const content = extractPasteContent(data);
    this.insertText(content);  // 一次插入
    this.invalidate();  // 只渲染一次
  }
}
```

### 7.2 撤销栈内存

**问题**：无限撤销栈可能占用大量内存。

**解决**：
```typescript
// 限制撤销栈大小
const MAX_UNDO = 100;

if (undoStack.length > MAX_UNDO) {
  undoStack.shift();  // 移除最旧的
}
```

## 8. 终端状态陷阱

### 8.1 异常退出恢复

**问题**：程序崩溃时终端可能处于 raw mode。

**坑点**：
```typescript
// 用户看到混乱的终端，输入不回显
```

**解决**：
```typescript
// 注册退出处理
process.on("exit", () => {
  terminal.stop();
});

process.on("SIGINT", () => {
  terminal.stop();
  process.exit(0);
});
```

### 8.2 Kitty 协议残留

**问题**：程序退出后 Kitty 协议可能仍然启用。

**解决**：
```typescript
terminal.stop();  // 自动发送 \x1b[<1u 禁用协议
```

## 10. 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| 终端无响应 | 未处理 SIGINT | 添加 process.on("SIGINT") |
| 输入不回显 | raw mode 未恢复 | 确保调用 terminal.stop() |
| 图像不显示 | 终端不支持 | 检测 capabilities |
| 焦点乱跳 | 多个组件竞争 | 使用 nonCapturing 覆盖层 |
| 中文错位 | 宽度计算错误 | 使用 visibleWidth |
| 按键无响应 | 序列解析失败 | 检查 Kitty 协议状态 |
| 闪烁严重 | diff 算法问题 | 检查 ANSI 序列一致性 |
| 内存泄漏 | 图像未清理 | 调用 deleteKittyImage |

## 11. 最佳实践

### 11.1 组件设计

```typescript
class MyComponent implements Component {
  private cache: string[] | null = null;

  render(width: number): string[] {
    if (this.cache) return this.cache;
    
    // 计算渲染结果
    this.cache = computeLines(width);
    return this.cache;
  }

  invalidate(): void {
    this.cache = null;
  }

  handleInput(data: string): void {
    if (matchesKey(data, Key.Enter)) {
      this.doSomething();
      this.invalidate();  // 标记需要重绘
      tui.render();       // 触发重绘
    }
  }
}
```

### 11.2 错误边界

```typescript
try {
  component.render(width);
} catch (error) {
  // 返回错误提示而不是崩溃
  return ["Error rendering component"];
}
```
