# pi-tui 状态机图

## 1. TUI 生命周期状态机

```
                    ┌─────────────┐
                    │   初始状态   │
                    │  (创建 TUI)  │
                    └──────┬──────┘
                           │ new TUI(terminal)
                           ▼
                    ┌─────────────┐
    ┌───────────────│   已创建    │
    │               │ (未启动)    │
    │               └──────┬──────┘
    │                      │ start()
    │                      ▼
    │               ┌─────────────┐
    │      ┌───────│   运行中    │◄─────────────────┐
    │      │       │ (接收输入)  │                  │
    │      │       └──────┬──────┘                  │
    │      │              │                         │
    │      │              │ requestRender()         │
    │      │              ▼                         │
    │      │       ┌─────────────┐                  │
    │      │       │  渲染队列中  │                  │
    │      │       │(nextTick)   │                  │
    │      │       └──────┬──────┘                  │
    │      │              │ process.nextTick()      │
    │      │              ▼                         │
    │      │       ┌─────────────┐                  │
    │      │       │   渲染中    │                  │
    │      │       │ (doRender)  │                  │
    │      │       └──────┬──────┘                  │
    │      │              │                         │
    │      │              └─────────────────────────┘
    │      │
    │      │       stop()
    │      │              │
    │      │              ▼
    │      │       ┌─────────────┐
    └──────────────►│   已停止    │
                    │ (恢复终端)  │
                    └─────────────┘
```

**关键状态说明**:
- **已创建**: TUI 实例已创建，但未启动，不接收输入
- **运行中**: 正常状态，接收并处理输入
- **渲染队列中**: `requestRender()` 已调用，等待 nextTick
- **渲染中**: 正在执行 `doRender()`，此时不处理新请求
- **已停止**: 恢复终端状态，退出

## 2. 渲染策略状态机

```
                    ┌─────────────┐
                    │   开始渲染   │
                    └──────┬──────┘
                           │
                           ▼
                    ┌─────────────┐
              否    │ previousLines │──►┌─────────────┐
        ┌───────────│  为空？      │    │  全量重绘    │
        │           └─────────────┘    │ (first render)│
        │           是                  └─────────────┘
        │              │
        │              ▼
        │      ┌─────────────┐
        │  是  │ widthChanged │──►┌─────────────┐
        │ ┌────│   或         │    │  全量重绘    │
        │ │    │ heightChanged│    │  (resize)   │
        │ │    │ (非 Termux)  │    └─────────────┘
        │ │    └─────────────┘
        │ │         否
        │ │          │
        │ │          ▼
        │ │ ┌─────────────┐
        │ │ │ firstChanged │──►┌─────────────┐
        │ └►│  < viewportTop│   │  全量重绘    │
        │   └─────────────┘    │ (scroll)    │
        │        否            └─────────────┘
        │         │
        │         ▼
        │  ┌─────────────┐
        │  │ firstChanged│──►┌─────────────┐
        │  │   === -1    │   │  仅光标移动  │
        │  │ (无变化)    │   │ (cursor only)│
        │  └─────────────┘   └─────────────┘
        │       否
        │        │
        │        ▼
        │ ┌─────────────┐
        └►│ firstChanged│
          │ >= newLines  │──►┌─────────────┐
          │ .length?      │   │  清除多余行  │
          └─────────────┘    │ (clear only) │
                否           └─────────────┘
                 │
                 ▼
          ┌─────────────┐
          │  增量更新    │
          │(differential)│
          └─────────────┘
```

**触发条件**:
- **全量重绘**: 首次渲染、宽度变化、高度变化（非 Termux）、变更在视口上方
- **仅光标移动**: 内容无变化，仅光标位置改变
- **清除多余行**: 内容缩短，需要清除旧行
- **增量更新**: 正常情况，只更新变更的行

4. 多层弹层：按 `focusOrder` 聚焦最上层

## 4. Kitty 键盘协议状态机

```
                    ┌─────────────┐
                    │  未检测     │
                    │ (初始)      │
                    └──────┬──────┘
                           │ start()
                           ▼
                    ┌─────────────┐
                    │  查询中     │
                    │ (发送查询)  │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            │            ▼
       ┌────────────┐      │     ┌────────────┐
       │ 收到响应    │      │     │ 超时无响应 │
       │ \\x1b[?<flags>u│      │     │            │
       └─────┬──────┘      │     └─────┬──────┘
             │             │           │
             │             │           │
             ▼             │           ▼
      ┌────────────┐       │    ┌────────────┐
      │ 已启用      │       │    │  传统模式   │
      │ Kitty协议   │◄──────┘    │ (Legacy)   │
      └─────┬──────┘            └────────────┘
            │
   ┌────────┼────────┐
   │        │        │
   ▼        ▼        ▼
┌──────┐ ┌──────┐ ┌──────┐
│press │ │repeat│ │release│
│事件   │ │事件  │ │事件   │
└──────┘ └──────┘ └──────┘
```

**协议检测流程**:
1. 启动时发送查询序列 `\x1b[?u`
2. 等待终端响应 `\x1b[?<flags>u`
3. 收到响应 → 启用 Kitty 协议，发送 `\x1b[>7u`
4. 超时 → 使用传统模式

**事件类型差异**:

| 事件 | 传统协议 | Kitty 协议 |
|------|----------|------------|
| 按下 | ✅ | ✅ (press) |
| 重复 | ❌ | ✅ (repeat) |
| 释放 | ❌ | ✅ (release) |
| 修饰键完整 | ❌ | ✅ |

## 5. StdinBuffer 状态机

```
                    ┌─────────────┐
                    │   空闲      │
                    │ (等待输入)  │
                    └──────┬──────┘
                           │
                           │ stdin 数据到达
                           ▼
                    ┌─────────────┐
                    │  缓冲中     │
                    │ (累积数据)  │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
       ┌────────────┐ ┌────────┐ ┌────────────┐
       │ 超时(10ms) │ │ 完整   │ │ 明显的     │
       │            │ │ 转义序列│ │ 序列边界   │
       └─────┬──────┘ └────┬───┘ └─────┬──────┘
             │             │           │
             │             │           │
             ▼             │           ▼
      ┌────────────┐       │    ┌────────────┐
      │ 触发 data  │◄──────┘    │ 触发 data  │
      │ 事件       │            │ 事件       │
      └─────┬──────┘            └─────┬──────┘
            │                        │
            └────────┐   ┌───────────┘
                     │   │
                     ▼   ▼
              ┌─────────────┐
              │  处理序列    │
              │ (parseKey)  │
              └─────────────┘
                     │
                     ▼
              ┌─────────────┐
              │   返回空闲   │
              └─────────────┘
```

**缓冲策略**:
- 超时：10ms 无新数据 → 发送已缓冲内容
- 完整序列：检测到完整转义序列 → 立即发送
- 边界检测：明显的字符边界 → 立即发送

**目的**: 解决 batched input 问题，确保组件接收独立的事件

## 8. 渲染请求合并状态机

```
                    ┌─────────────┐
                    │  空闲       │
                    │(无待渲染)   │
                    └──────┬──────┘
                           │ requestRender()
                           ▼
                    ┌─────────────┐
                    │  已请求     │
                    │(等待nextTick)│
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            │            ▼
       ┌────────────┐      │     ┌────────────┐
       │ 再次请求    │      │     │ nextTick   │
       │ requestRender│     │     │ 触发       │
       │()           │     │     │            │
       └─────┬──────┘      │     └─────┬──────┘
             │             │           │
             │ (忽略，合并) │           │
             │             │           │
             └─────────────┴───────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │   渲染中    │
                    │ (doRender)  │
                    └──────┬──────┘
                           │
                           │ 完成
                           ▼
                    ┌─────────────┐
                    │   空闲      │
                    └─────────────┘
```

**合并机制**:
- `requestRender()` 设置 `renderRequested = true`
- 同一 tick 内的多次调用被合并
- `process.nextTick()` 执行实际渲染
- 渲染完成后 `renderRequested = false`

**force 参数**:
- `requestRender(true)` 强制全量重绘
- 重置 `previousLines = []`，触发首次渲染逻辑
