# coding-agent 问题与坑

## 1. 会话文件格式

### 1.1 JSON Lines 格式陷阱

**问题**：会话文件使用 JSON Lines 格式，每行一个 JSON 对象。

**坑点**：
- 最后一行可能缺少换行符
- 某些编辑器可能添加 BOM
- 大文件读取时内存占用高

**解决**：
```typescript
// 使用 readline 逐行读取
import { createReadStream } from "fs";
import { createInterface } from "readline";

const lines = createInterface({
  input: createReadStream(sessionFile)
});

for await (const line of lines) {
  const entry = JSON.parse(line);
  // 处理 entry
}
```

---

### 1.2 Entry ID 冲突

**问题**：`randomUUID()` 在极端情况下可能重复（理论上）。

**坑点**：
- 并发快速创建 entry 时
- 某些 UUID 实现可能有 bug

**解决**：
- pi 使用 Node.js 原生 `randomUUID()`，质量有保障
- 如果真的冲突，后续 entry 的 `parentId` 可能指向错误

## 2. 工具执行

### 2.1 Bash 命令注入

**问题**：Bash 工具直接执行用户输入的命令。

**坑点**：
- LLM 可能生成危险命令 (`rm -rf /`)
- 当前工作目录可能不是预期的

**解决**：
```typescript
// 验证 cwd 是预期的项目目录
if (!cwd.startsWith(expectedProjectRoot)) {
  throw new Error("CWD outside project");
}

// 或者使用沙箱
const bashTool = createBashTool(cwd, { 
  timeout: 30000,
  allowedCommands: ['ls', 'cat', 'grep'] // 白名单
});
```

---

### 2.2 工具超时处理

**问题**：长时间运行的命令可能超时。

**坑点**：
- 超时后进程可能还在运行（僵尸进程）
- `timeout` 参数与 shell 内置的 `timeout` 混淆

**解决**：
```typescript
// pi 的实现
const timeout = setTimeout(() => {
  process.kill();  // SIGTERM
  setTimeout(() => process.kill('SIGKILL'), 5000);  // 强制杀死
}, timeoutMs);
```

---

### 2.3 Edit 工具的 Diff 匹配

**问题**：`edit` 工具使用 `oldString` 匹配替换。

**坑点**：
- 文件内容已变化，导致 `oldString` 不匹配
- 多行字符串的空白差异

**解决**：
- pi 使用模糊匹配（可能）
- 建议 LLM 先 `read` 确认内容

---

## 3. 扩展系统

### 3.1 扩展加载失败

**问题**：扩展代码可能有语法错误或运行时错误。

**坑点**：
- 一个扩展失败可能影响其他扩展
- 错误信息不够详细

**解决**：
```typescript
// pi 的实现
for (const extDir of extensions) {
  try {
    const ext = await loadExtension(extDir);
    extensions.push(ext);
  } catch (error) {
    console.error(`Failed to load extension ${extDir}:`, error);
    // 继续加载其他扩展
  }
}
```

---

### 3.2 扩展 API 版本兼容性

**问题**：扩展可能使用旧版 API。

**坑点**：
- API 变更后扩展可能失效
- 没有版本检查

**解决**：
- 扩展声明兼容的 pi 版本
- pi 检查扩展版本兼容性

## 4. 上下文压缩

### 4.1 压缩时机

**问题**：压缩可能在对话中间触发。

**坑点**：
- 用户体验：突然看到"正在压缩..."
- 压缩失败可能丢失上下文

**解决**：
```typescript
// 手动触发压缩
await agentSession.compact("manual");

// 或在合适的时机自动压缩
if (shouldCompact(context) && !isInMiddleOfTurn) {
  await agentSession.compact("threshold");
}
```

---

### 4.2 摘要质量

**问题**：LLM 生成的摘要可能丢失关键信息。

**坑点**：
- 重要决策细节被省略
- 后续对话引用被压缩的内容

**解决**：
- 使用分支摘要保留关键决策
- 定期手动审查压缩效果

## 5. 认证与凭证

### 5.1 OAuth Token 过期

**问题**：OAuth Token 有有效期（通常 1-2 小时）。

**坑点**：
- 长对话中 Token 可能过期
- 需要自动刷新

**解决**：
```typescript
// pi 的实现
const credentials = authStorage.getOAuthCredential("anthropic");
if (Date.now() >= credentials.expires) {
  const newCredentials = await refreshOAuthToken(credentials);
  authStorage.setOAuthCredential("anthropic", newCredentials);
}
```

---

### 5.2 API Key 安全

**问题**：API Key 存储在本地文件 `~/.pi/agent/auth.json`。

**坑点**：
- 文件权限可能过于宽松
- 备份时可能包含敏感信息

**解决**：
```bash
# 设置文件权限
chmod 600 ~/.pi/agent/auth.json

# .gitignore 忽略
# ~/.pi/agent/
```

## 6. Skill 系统

### 6.1 Skill 名称冲突

**问题**：多个 Skill 可能有相同名称。

**坑点**：
- 后加载的覆盖先加载的
- 用户难以发现冲突

**解决**：
- pi 验证 `name` 与目录名一致
- 命名空间前缀：`@user/skill-name`

---

### 6.2 Skill Frontmatter 解析

**问题**：YAML frontmatter 格式错误。

**坑点**：
- 缺少 `---` 分隔符
- YAML 语法错误

**解决**：
```typescript
// pi 的实现
try {
  const frontmatter = parseFrontmatter(content);
} catch (error) {
  diagnostics.push({
    severity: "error",
    message: `Invalid frontmatter: ${error.message}`
  });
}
```

## 7. 设置管理

### 7.1 设置持久化

**问题**：设置保存在文件，并发修改可能冲突。

**坑点**：
- 多个进程同时修改 `settings.json`
- 数据丢失

**解决**：
```typescript
// pi 使用 proper-lockfile
import lockfile from "proper-lockfile";

await lockfile.lock(settingsPath);
try {
  // 读取、修改、写入
} finally {
  await lockfile.unlock(settingsPath);
}
```

## 8. 资源加载

### 8.1 路径解析

**问题**：路径可能包含 `~` 或相对路径。

**坑点**：
- `~` 未展开为 home 目录
- 相对路径解析错误

**解决**：
```typescript
import { homedir } from "os";
import { resolve } from "path";

function resolvePath(input: string): string {
  if (input === "~") return homedir();
  if (input.startsWith("~/")) return homedir() + input.slice(1);
  return resolve(input);
}
```

## 9. 性能陷阱

### 9.1 大文件读取

**问题**：`read` 工具读取大文件。

**坑点**：
- 内存溢出
- Token 计算不准确

**解决**：
- 使用 `offset` 和 `limit` 参数
- 自动截断大文件

---

### 9.2 Grep/Find 性能

**问题**：在大型代码库中搜索。

**坑点**：
- 搜索时间过长
- 结果过多

**解决**：
- 使用 `ripgrep` (rg) 替代 `grep`
- 限制结果数量

## 11. 常见错误

| 错误 | 原因 | 解决 |
|------|------|------|
| `ENOENT: session file not found` | 会话 ID 错误或文件被删除 | 检查 `~/.pi/agent/sessions/` |
| `Tool "xxx" not found` | 工具未注册或拼写错误 | 检查扩展加载 |
| `Context overflow` | 上下文超出限制 | 手动压缩或切换会话 |
| `OAuth token expired` | Token 过期 | 重新登录 |
| `Bash timeout` | 命令执行超时 | 增加 timeout 参数 |
| `Edit failed: oldString not found` | 文件内容已变化 | 重新读取文件 |
| `Extension API version mismatch` | 扩展 API 版本不兼容 | 更新扩展 |
| `Settings file corrupted` | JSON 格式错误 | 恢复备份或重置 |

## 12. 最佳实践

### 12.1 会话管理

- 定期创建新会话，避免单个会话过大
- 使用分支保存实验性对话
- 重要的会话定期导出 HTML 备份

### 12.2 工具使用

- 复杂编辑前先用 `read` 确认内容
- Bash 命令先测试再执行
- 使用 `grep`/`find` 缩小范围后再 `read`

### 12.3 扩展开发

- 使用 TypeScript 类型检查
- 处理所有错误情况
- 提供详细的诊断信息

### 12.4 配置管理

- 不同项目使用不同的设置
- API Key 使用环境变量或密钥管理工具
- 定期备份 `~/.pi/agent/` 目录
