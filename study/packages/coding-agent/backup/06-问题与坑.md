# Coding Agent 问题与坑

## 1. 设计决策与权衡

### 1.1 为什么不做 MCP?

**官方立场**: Pi 选择不做 MCP (Model Context Protocol)，而是推荐两种方式：

1. **Skills** - 简单的 Markdown 文件，包含使用说明
2. **Extensions** - TypeScript 模块，完全控制

**原因**:
> "MCP 解决的是不同客户端与不同服务器之间的互操作问题。但 Pi 只有一个客户端（自身），扩展直接在 Pi 进程内运行，不需要跨进程通信。"

**对比**:
| 方式 | 复杂度 | 能力 | 适用场景 |
|------|--------|------|----------|
| Skills | 低 | 提示词指导 | 简单工作流 |
| Extensions | 中 | 完全控制 | 自定义工具/UI |
| MCP | 高 | 跨进程 | 多客户端共享 |

---

### 1.2 为什么不做子代理 (Sub-agents)?

**官方立场**: Pi 不提供内置子代理，但可以通过以下方式实现：

1. **tmux** - 多窗口运行多个 pi 实例
2. **Extensions** - 自己实现子代理逻辑
3. **Pi Packages** - 安装社区实现的方案

**原因**:
> "子代理的实现方式有很多，取决于具体需求：是并发执行、串行执行、还是需要共享上下文？Pi 保持核心最小，让用户选择最适合的方式。"

---

### 1.3 为什么不做权限弹窗?

**官方立场**: Pi 没有内置的权限确认弹窗（如"是否允许执行此命令？"）。

**推荐做法**:
1. **容器运行** - 在受限环境中执行
2. **Extension 拦截** - 自己实现权限控制

**代码示例**:
```typescript
// extension 实现权限控制
api.on("tool_call", async (event, ctx) => {
  if (event.toolName === "bash") {
    const allowed = await ctx.ui.confirm(
      "Permission",
      `Allow: ${event.input.command}?`
    )
    if (!allowed) {
      return { block: true, message: "User denied" }
    }
  }
})
```

## 2. 边界情况与陷阱

### 2.1 会话存储

**陷阱 1**: JSONL 文件可能变得很大
- 长会话的 JSONL 文件可能达到 MB 级别
- 压缩后旧消息仍存在文件中（只是摘要替代）
- **解决方案**: 定期清理或分叉新会话

**陷阱 2**: 会话恢复时模型可能不可用
- 保存会话时使用的模型，恢复时可能已卸载/不可访问
- **处理**: `modelFallbackMessage` 提示用户

### 2.2 扩展系统

**陷阱 1**: 扩展加载失败不会阻止启动
- 单个扩展加载失败只记录错误，pi 继续启动
- **检查**: 启动时查看 stderr 的扩展错误

**陷阱 2**: 扩展是单例，但代码可能被重新加载
- `/reload` 会重新加载扩展代码
- 注意清理旧的事件监听器和资源

```typescript
export default function (api: ExtensionAPI) {
  const cleanup: (() => void)[] = []
  
  // 订阅事件
  const unsub = api.on("agent_start", handler)
  cleanup.push(unsub)
  
  // 返回 cleanup 函数（可选）
  return () => {
    cleanup.forEach(fn => fn())
  }
}
```

### 2.3 工具执行

**陷阱 1**: 工具默认并行执行
- 多个 tool_calls 同时执行
- **控制**: 使用 extension 的 `setBeforeToolCall` 实现串行

**陷阱 2**: Bash 工具超时默认 60 秒
- 长运行命令会被中断
- **配置**: `bashTool({ timeout: 300000 })` (5分钟)

### 2.4 上下文压缩

**陷阱 1**: 压缩是 lossy 的
- 旧消息被摘要替代，详细信息丢失
- **恢复**: 使用 `/tree` 查看原始历史

**陷阱 2**: 压缩触发时可能有延迟
- 阈值触发时会暂停响应进行压缩
- **体验**: 大模型或长会话时可能感知到卡顿

### 2.5 配置加载

**陷阱 1**: 配置优先级容易混淆

优先级（高到低）：
1. CLI 参数 (`--model`)
2. 环境变量 (`ANTHROPIC_API_KEY`)
3. 项目配置 (`.pi/settings.json`)
4. 用户配置 (`~/.pi/agent/settings.json`)
5. 默认值

**陷阱 2**: `--session` 和 `--continue` 互斥
- 同时指定会报错
- **选择**: 二选一

## 3. 常见错误

### 3.1 "No models available"

**原因**: 
- 未设置 API Key
- 模型配置错误

**解决**:
```bash
# 方式 1: 环境变量
export ANTHROPIC_API_KEY=sk-ant-...

# 方式 2: /login 命令
pi
> /login

# 方式 3: auth.json
echo '{"anthropic": {"apiKey": "sk-ant-..."}}' > ~/.pi/agent/auth.json
```

### 3.2 "Context overflow"

**原因**: 会话太长，超过模型上下文限制

**解决**:
1. 自动压缩已启用时会自动处理
2. 手动压缩: `/compact`
3. 开新会话: `/new`

### 3.3 Extension "..." failed to load

**原因**:
- TypeScript 编译错误
- 缺少依赖
- 语法错误

**调试**:
```bash
# 单独测试扩展
npx ts-node path/to/extension.ts

# 查看详细错误
pi --verbose
```

## 4. 性能考量

### 4.1 会话文件过大

**症状**: 启动变慢，/tree 命令卡顿

**诊断**:
```bash
ls -lh ~/.pi/agent/sessions/
```

**解决**:
- 定期使用 `/fork` 创建新会话
- 手动清理旧会话文件
- 配置 `sessionDir` 到项目目录便于管理

### 4.2 扩展过多

**症状**: 启动慢，内存占用高

**诊断**:
```bash
# 查看加载的扩展
pi /reload
# 启动日志显示扩展数量
```

**解决**:
- 使用 `--no-extensions` + `-e ./only-this.ts` 仅加载必要扩展
- 合并功能相近的扩展
- 延迟加载（在事件处理器中动态导入）

### 4.3 图片处理

**症状**: 粘贴图片后响应慢

**原因**: 
- 大图片自动调整尺寸需要时间
- 图片 token 占用上下文

**配置**:
```json
// settings.json
{
  "imageAutoResize": true,  // 自动压缩图片
  "maxImageSize": 1024      // 最大边长
}
```

## 5. 最佳实践

### 5.1 会话管理

```bash
# 项目本地会话（推荐）
cd my-project
pi  # 会话自动保存到 .pi/sessions/

# 定期分叉
pi /fork

# 清理旧会话
rm ~/.pi/agent/sessions/old-session-*.jsonl
```

### 5.2 扩展开发

```typescript
// ✅ 好的做法：清理资源
export default function (api: ExtensionAPI) {
  const disposables: (() => void)[] = []
  
  disposables.push(api.on("agent_start", () => {
    console.log("Agent started")
  }))
  
  disposables.push(api.registerTool({
    name: "my-tool",
    // ...
  }))
  
  return () => {
    disposables.forEach(d => d())
  }
}

// ❌ 坏的做法：不清理
export default function (api: ExtensionAPI) {
  setInterval(() => {}, 1000)  // 泄漏定时器
  api.on("agent_start", () => {})  // 泄漏监听器
}
```

### 5.3 工具开发

```typescript
// ✅ 好的做法：返回结构化数据
api.registerTool({
  name: "search",
  async execute({ query }) {
    const results = await search(query)
    return {
      content: `Found ${results.length} results`,
      details: { results }  // 结构化数据
    }
  }
})

// ❌ 坏的做法：只返回文本
api.registerTool({
  name: "search",
  async execute({ query }) {
    const results = await search(query)
    return {
      content: JSON.stringify(results)  // LLM 难解析
    }
  }
})
```

## 6. 版本兼容性

### 6.1 配置文件版本

Pi 会自动迁移旧版本配置：
- `settings.json` - 自动迁移
- `keybindings.json` - 自动迁移
- `auth.json` - 自动迁移

**手动迁移**:
```bash
pi /reload
# 查看启动日志的迁移信息
```

### 6.2 扩展 API 版本

Extension API 可能随版本变化：
- 关注 CHANGELOG.md 的破坏性变更
- 使用 TypeScript 获得类型检查

**兼容性检查**:
```typescript
// 检查 API 版本
if (api.VERSION && api.VERSION < "0.60.0") {
  throw new Error("Requires pi >= 0.60.0")
}
```
