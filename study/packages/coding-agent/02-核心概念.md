# coding-agent 核心概念

## 1. AgentSession (核心抽象)

### 1.1 职责

`AgentSession` 是 coding-agent 的核心类，封装了：
- Agent 状态访问
- 事件订阅与自动持久化
- 模型和推理级别管理
- 上下文压缩 (手动/自动)
- Bash 执行
- 会话切换和分支

### 1.2 配置

```typescript
interface AgentSessionConfig {
  agent: Agent;                          // pi-agent-core 的 Agent
  sessionManager: SessionManager;        // 会话管理器
  settingsManager: SettingsManager;      // 设置管理器
  cwd: string;                           // 当前工作目录
  scopedModels?: Array<{                 // Ctrl+P 循环的模型
    model: Model<any>;
    thinkingLevel?: ThinkingLevel;
  }>;
  resourceLoader: ResourceLoader;        // 资源加载器
  customTools?: ToolDefinition[];        // 自定义工具
  modelRegistry: ModelRegistry;          // 模型注册表
  initialActiveToolNames?: string[];     // 初始激活的工具
  baseToolsOverride?: Record<string, AgentTool>; // 覆盖基础工具
  extensionRunnerRef?: { current?: ExtensionRunner }; // 扩展运行时引用
}
```

### 1.3 事件系统

```typescript
type AgentSessionEvent =
  | AgentEvent                                // pi-agent-core 事件
  | { type: "compaction_start"; reason: "manual" | "threshold" | "overflow" }
  | { type: "compaction_end"; reason: ...; result: CompactionResult; aborted: boolean; ... }
  | { type: "auto_retry_start"; attempt: number; maxAttempts: number; ... }
  | { type: "auto_retry_end"; success: boolean; attempt: number; ... };
```

### 1.4 核心方法

| 方法 | 用途 |
|------|------|
| `prompt(text, options)` | 发送用户消息，启动 Agent 循环 |
| `cycleModel()` | 切换模型 (Ctrl+P) |
| `cycleThinkingLevel()` | 切换推理级别 |
| `compact(reason?)` | 手动压缩上下文 |
| `fork(newCwd?)` | 创建会话分支 |
| `switchSession(sessionId)` | 切换会话 |
| `executeBash(command, options?)` | 执行 Bash 命令 |
| `addEventListener(listener)` | 订阅事件 |
| `removeEventListener(listener)` | 取消订阅 |

## 2. 会话管理 (Session)

### 2.1 会话文件结构

会话以 JSON Lines 格式存储，每行是一个 JSON 对象：

```jsonl
{"type":"session","version":3,"id":"abc123","timestamp":"...","cwd":"/home/user/project"}
{"type":"message","id":"1","parentId":null,"timestamp":"...","message":{...}}
{"type":"message","id":"2","parentId":"1","timestamp":"...","message":{...}}
{"type":"thinking_level_change","id":"3","parentId":"2",...}
```

### 2.2 SessionEntry 类型

```typescript
type SessionEntry =
  | SessionMessageEntry      // AgentMessage
  | ThinkingLevelChangeEntry // 推理级别变更
  | ModelChangeEntry         // 模型变更
  | CompactionEntry          // 压缩摘要
  | BranchSummaryEntry       // 分支摘要
  | CustomEntry              // 扩展自定义数据
  | CustomMessageEntry       // 扩展自定义消息
  | LabelEntry               // 用户标记
  | SessionInfoEntry;        // 会话元数据
```

### 2.3 会话树结构

会话支持树状结构（分支）：

```
session-abc/
├── main.jsonl          # 主分支
├── branch-def.jsonl    # 分支 1
└── branch-ghi.jsonl    # 分支 2
```

每个 entry 有 `id` 和 `parentId`，形成链表结构。

## 3. 工具系统 (Tools)

### 3.1 内置工具

| 工具 | 功能 | Schema 示例 |
|------|------|-------------|
| **read** | 读取文件 | `{ path: string, offset?: number, limit?: number }` |
| **bash** | 执行命令 | `{ command: string, timeout?: number }` |
| **edit** | 编辑文件 | `{ path: string, oldString: string, newString: string }` |
| **write** | 写入文件 | `{ path: string, content: string }` |
| **grep** | 搜索文本 | `{ pattern: string, path?: string }` |
| **find** | 查找文件 | `{ pattern: string, path?: string }` |
| **ls** | 目录列表 | `{ path: string }` |

### 3.2 工具定义

```typescript
interface ToolDefinition<TInput = unknown, TDetails = unknown> {
  name: string;
  description: string;
  parameters: TSchema;           // TypeBox schema
  execute: (input: TInput, context: ToolContext) => Promise<ToolResult<TDetails>>;
}
```

### 3.3 工具分类

```typescript
// 只读工具 (safe)
const readOnlyTools = [readTool, grepTool, findTool, lsTool];

// 编码工具 (read + write)
const codingTools = [readTool, bashTool, editTool, writeTool];

// 全部工具
const allTools = { read, bash, edit, write, grep, find, ls };
```

### 3.4 工具工厂函数

```typescript
// 创建工具实例 (带 cwd)
const tools = createCodingTools("/home/user/project");

// 创建工具定义
const definitions = createCodingToolDefinitions("/home/user/project");

// 创建只读工具
const readOnly = createReadOnlyTools("/home/user/project");
```

### 4.1 Extension 接口

```typescript
interface Extension {
  name: string;
  version: string;
  description?: string;

  // 生命周期
  setup?(api: ExtensionAPI): void | Promise<void>;

  shutdown?(): void | Promise<void>;

  // 事件处理器
  onAgentStart?(event: AgentStartEvent): void | Promise<void>;
  onTurnStart?(event: TurnStartEvent): void | Promise<void>;
  onToolCall?(event: ToolCallEvent): Promise<ToolCallEventResult | void>;
  onMessageEnd?(event: MessageEndEvent): void | Promise<void>;
  // ... 更多事件
}
```

### 4.2 扩展 API

```typescript
interface ExtensionAPI {
  // 注册命令
  registerCommand(name: string, handler: CommandHandler): void;
  
  // 注册工具
  registerTool(definition: ToolDefinition): void;
  
  // 发送消息
  sendUserMessage(content: string): Promise<void>;
  
  // 显示对话框
  showDialog(options: ExtensionUIDialogOptions): Promise<string>;
  
  // 访问会话
  getSessionContext(): SessionContext;
  
  // 添加快捷键
  addKeybinding(keybinding: AppKeybinding): void;
}
```

### 4.3 事件类型

| 类别 | 事件 |
|------|------|
| **Agent** | `agent_start`, `agent_end` |
| **Turn** | `turn_start`, `turn_end` |
| **Message** | `message_start`, `message_update`, `message_end` |
| **Tool** | `toolcall_start`, `toolcall_end`, `tool_execution_start`, `tool_execution_end` |
| **Session** | `session_start`, `session_switch`, `session_fork` |

## 6. 上下文压缩 (Compaction)

### 6.1 触发条件

| 原因 | 说明 |
|------|------|
| `manual` | 用户手动触发 (/compact) |
| `threshold` | 达到 token 阈值 |
| `overflow` | 超出模型上下文窗口 |

### 6.2 压缩流程

```
1. 检查是否需要压缩 (shouldCompact)
   - 计算当前上下文 token 数
   - 与阈值比较

2. 准备压缩 (prepareCompaction)
   - 找到切割点 (findCutPoint)
   - 收集保留的 entries

3. 生成摘要 (generateSummary)
   - 发送被移除的对话给 LLM
   - 生成简洁摘要

4. 创建 CompactionEntry
   - 存储摘要到会话文件
   - 保留的 entries 链接到摘要

5. 构建新上下文
   - 系统提示
   - CompactionEntry (作为 history)
   - 保留的 entries
```

### 6.3 CompactionEntry

```typescript
interface CompactionEntry<T = unknown> {
  type: "compaction";
  summary: string;              // LLM 生成的摘要
  firstKeptEntryId: string;     // 第一个保留 entry 的 ID
  tokensBefore: number;         // 压缩前的 token 数
  details?: T;                  // 扩展特定数据
  fromHook?: boolean;           // 是否由扩展生成
}
```

## 10. 运行模式

### 10.1 Interactive Mode (TUI)

- 基于 pi-tui 的交互式界面
- 支持实时预览工具调用
- 支持图片渲染
- 支持快捷键操作

### 10.2 Print Mode

- 非交互式输出
- 适合脚本调用
- 支持 JSON 输出

### 10.3 RPC Mode

- 通过 stdin/stdout 通信
- 支持程序化控制
- 用于编辑器插件
